# 官方训练包接入与十轮续训设计

## 1. 目标

在不修改原始训练包、不接触隐藏测试、不调用SwanLab或平台提交接口的前提下，将A/B/C三个官方训练包接入BRACE-MSI。所有候选必须从随包`checkpoint.npz`及其Adam、标准化和目标缩放状态继续训练，完成可恢复的十轮决策、候选验证、部署或保留旧模型，并分别报告性能与资源。

本阶段属于“官方训练包本地开发验证”，不是平台试运行、正式评测或官方成绩。训练包自身将报告标记为`purpose=development_reference`及`official_scoring_ready=false`，所有项目产物必须保留该边界。

## 3. 选定方案

采用“外部只读官方包 + 校验清单 + 隔离子进程训练 + BRACE监督器”。不把60MB公开数据或检查点提交进Git，也不把模型权重打入Docker镜像。

未采用的方案：

- 不把官方训练器代码复制后重写为项目模型类，避免算法漂移和证据链断裂。
- 不使用纯PowerShell固定十轮脚本，因为它无法复用现有预算、门控、恢复和审计能力。
- 不直接在当前Python进程依次导入三个同名`baselines`包，避免模块缓存导致跨包加载错误。

## 4. 架构

### 4.1 训练包清单

`OfficialPackageManifest`只读扫描三个包，验证必需文件、文件哈希、`training.json`、`baseline-info.json`、配置、检查点元数据和公开数据摘要。任何哈希、任务、特征schema、参数量、父检查点或行数不一致都在训练前失败。

清单只保存路径、大小、哈希和聚合数据统计，不复制逐样本内容，不修改原目录。

### 4.2 官方训练适配器

`OfficialBaselineAdapter`通过独立Python子进程，从对应包目录调用原版：

```text
python -m baselines.train --profile <A|B|C>
  --train public/train.jsonl --validation public/validation.jsonl
  --from-baseline|--resume <parent checkpoint>
  --epochs <bounded> --learning-rate <bounded> --batch-size <bounded>
  --output <new candidate directory> --stage-id <round/candidate>
```

适配器不解析或执行模型生成代码，只执行清单白名单中的训练入口。候选完成后验证：输出目录此前不存在、父SHA与实际稳定检查点相同、参数量与schema未变化、指标有限、检查点可由官方`Model.load`读取、训练报告哈希与实物一致。

### 4.3 十轮监督器

每个任务和策略从同一官方初始检查点开始，严格运行10个**候选适应决策轮**。官方包没有下发真实时间批次或漂移流，因此这些轮次只表示反复“读历史—选择候选—续训—公开验证—部署/拒绝”，不得表述为真实漂移流评测。静态官方检查点仅作基线；比较策略为简单性能触发式续训与BRACE。

- 简单策略：当历史最佳公开验证指标未达到或出现退化时，执行基线学习率下的1 epoch续训；否则允许`noop`。
- BRACE：根据已实现的历史收益、失败、剩余预算和风险证据，从有限白名单中选择1、2、3或5 epochs及基线学习率的0.25、0.5或1.0倍；批大小仅允许基线值或2倍。
- 每轮最多训练一个候选；候选始终从当前稳定检查点开始。候选通过门控才成为下一轮父检查点，否则下一轮仍从旧稳定检查点开始。
- 为满足真实闭环证据，每个BRACE任务至少执行3次真实候选；不得用`noop`、预算拒绝或失败启动冒充训练迭代。
- 选择器只能读取此前轮次的聚合结果，不读取未来轮次、隐藏数据或平台评分。

门控硬约束包括哈希、schema、父检查点、预算、有限指标和可加载性。部署层以公开验证主指标相对稳定模型的变化为准；A要求Macro-F1不下降，B/C要求RMSE不增加。相等结果优先保留旧模型，避免无收益更新。公开验证用于选型，因此最终结论只能等待平台隐藏测试确认。

父模型继承必须由模型状态证明，而不是仅记录`parent_checkpoint_sha256`：适配器将验证子检查点累计epoch/step严格增加、权重或Adam状态相对父模型发生变化，并以“从同一父模型连续2 epoch”与“1 epoch后从子检查点再续1 epoch”的确定性等价测试证明原版训练器真实恢复全部状态。被拒绝候选绝不进入稳定父模型链。

每次读取公开验证集都写入验证使用账本，记录任务、策略、轮次、候选、用途和累计暴露次数。公开验证不得进入`--train`、标准化或目标缩放拟合；每轮最多一个候选，不在同一实验完成后根据结果修改动作空间重跑。报告必须单列验证反复选择导致的过拟合风险。

### 4.4 运行与恢复

运行根固定为`D:/brace-msi-official-package/OFFICIAL-PACKAGE-DEV-001/`，包含：

- `source-manifest.json`：输入哈希和聚合审计；
- `smoke/`：每任务独立1 epoch候选；
- `experiments/<task>/<policy>/round-XX/`：原版训练器输出；
- `state.json`：原子更新的当前轮次、稳定检查点和预算；
- `audit.jsonl`：不含逐样本特征/标签的决策记录；
- `summary.json`、`report.md`、`report.html`和`validation.json`。

进程限制为最多4个逻辑CPU，训练子进程设置`BASELINE_CPU_THREADS=1`，并记录墙钟、CPU、RSS、训练行数及候选数。输出目录已存在时只允许验证并跳过，禁止覆盖。子进程异常、超时、报告不一致或指标非有限时保留失败目录、保持稳定检查点并停止当前策略，其他独立任务可继续。

### 4.5 无人值守执行顺序

1. 只读清单审计和官方包自测；
2. 根据包内历史训练耗时、候选上限和检查点体积生成CPU时间、磁盘与运行时长的保守预估；超过本地预算则在训练前停止；
3. A、B、C各一个1 epoch Smoke，检查父哈希、真实状态继承、模型可加载、指标和原子输出，并用实测更新资源估算；
4. 三个静态基线机器复核；
5. 按A→B→C顺序完成简单策略十轮；
6. 按A→B→C顺序完成BRACE十轮；
7. 每完成一个任务原子保存状态；断点恢复不重复已完成候选；
8. 生成配对汇总，但不计算未公开的官方综合分。

前三个Smoke完成后检查一次健康状态；其余任务可以隐藏后台进程脱离聊天继续。

## 5. 测试

- 清单：缺文件、哈希变化、错误任务、B错误拓扑、训练/验证重叠均应在训练前失败。
- 适配器：验证真实官方检查点、父SHA绑定、全状态续训、输出目录不可覆盖和子进程失败保留。
- 继承证明：验证连续2 epoch与1+1恢复训练产生相同权重、Adam、epoch、step和预测；拒绝候选的SHA不得出现在下一轮父链。
- 策略：固定输入历史下动作确定；预算耗尽、无收益、退化、失败升级和至少3次真实候选规则可测试。
- 恢复：在轮次完成后中断并重启，不重复训练或改变结果哈希。
- 端到端：三任务Smoke后再运行完整队列；机器验收检查10轮、父链、有限指标、资源、无密封数据、无SwanLab和无平台调用。

## 6. 完成标准

- 三个官方包哈希清单、数据隔离、检查点结构和基线指标均有机器证据；
- 三任务Smoke通过；简单策略和BRACE各完成10个决策轮；BRACE每任务至少3次真实候选；
- 所有候选的父检查点、官方训练报告、资源和门控结果可追溯；
- 运行可断点恢复，错误不覆盖稳定模型或旧证据；
- 生成静态报告与机器验收，明确`official_package=true`、`official_scoring_ready=false`；
- 资源预估与Smoke实测均证明后台队列在本地预算内；验证使用账本完整，报告明确候选适应轮次而非真实漂移流；
- 完整项目回归通过，Git提交和工作树干净；
- SwanLab、平台试跑、隐藏测试、Docker权重打包均未发生。

## 7. 停止条件

发现原始包哈希变化、训练/验证身份交叉、检查点父链不一致、官方训练器无法加载、非有限指标、超过4核/8GB本地边界、输出目录冲突，或需要猜测平台隐藏协议时立即停止并登记证据。
