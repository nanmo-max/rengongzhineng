# RELEASE-READINESS 执行清单

本清单只覆盖正式候选系统的发布工程，不修改BRACE-MSI架构、算法或已锁定实验结论。
`LOCAL-FORMAL-SIM-001-A1`继续保留为`INVALID`负证据，A2继续作为本地代理工程验收证据；
本阶段不重跑密封实验。

## 任务1：实际容器运行时验收

- 检测Docker/Podman/WSL和虚拟化条件。
- 在可用运行时中构建Linux镜像，记录镜像ID、压缩前大小和构建日志。
- 使用`--network=none --cpus=4 --memory=8g`运行合成安装验收，不运行代理密封数据。
- 若运行时缺失或安装需要重启/管理员交互，登记`BLOCKED`，不得用静态上下文替代。

## 任务2：干净环境依赖与回归

- 创建独立Python环境，只安装候选锁文件和项目本身。
- 执行`pip check`、完整测试、CLI Smoke、包审计和编译检查。
- 保存环境清单和命令结果，不修改全局Anaconda依赖。

## 任务3：SwanLab适配准备

- 只依据SwanLab官方文档实现可选、脱敏、离线优先的同步适配器。
- 未安装SDK时核心Harness仍可运行；安装后可生成官方离线日志并由人工显式执行同步。
- 不自动上传、不记录私有样本、密钥或可逆特征；比赛正式字段规范仍保持阻塞。

## 任务4：正式SDK适配器准备

- 提供平台无关的适配器骨架、字段映射配置和契约测试。
- 官方模块、字段、标签权限与错误码均由注入配置提供，禁止写死宣讲转写。
- 缺少官方SDK时只验证契约与失败模式，不声称完成正式接入。

## 任务5：Release Candidate审计

- 审计代码、配置、日志、许可证、镜像/容器证据、SwanLab接口、SDK接入文档和恢复说明。
- 生成可机读清单与人工审计报告，明确`PASS`、`BLOCKED`和外部依赖。
- 运行完整回归并提交发布候选；不合并`main`。

## 完成边界

所有本机可完成项均有新鲜证据且Git已提交；真实SDK、官方数据、官方评分和正式SwanLab
字段规范继续标记`BLOCKED`。若本机无容器运行时，则镜像构建和4核8GB Linux容器验收也保持
`BLOCKED`，不得制造通过证据。
