# PERF-A-REPLAY-001 持续学习协议

## 研究问题

源Batch 1过采样不能恢复Batch 2的Acetaldehyde。本实验改为符合比赛闭环的因果顺序：稳定模型先预测当前批次；随后才获得当前标签、构建候选并门控；候选只能影响下一批预测。

## 策略

三个策略共享官方A初始检查点、批次、当前批次训练/门控切分、epoch和学习率：

1. `current_only`：只训练当前已标注批次的80%训练部分；
2. `uniform_replay_600`：当前训练部分加历史已标注样本的固定哈希均匀缓冲区；
3. `class_balanced_replay_600`：当前训练部分加按类别均分容量、类内固定哈希选样的历史缓冲区。

类平衡回放受ICML 2020《Online Continual Learning from Imbalanced Data》的问题设定与CBRS思想启发，但该论文未提供可核验官方代码，因此本轮只称“独立实现的强基线”，不称论文代码复现，也不登记为正式论文插件。

## 数据可见性

- Batch 2—5：开发流，用于策略选择；每批先对全批预测，再使用标签。
- Batch 6—7：确认流，只在开发配置与状态冻结后运行；不依据确认结果改策略。
- Batch 8—10：本实验禁止加载。
- 每个已反馈批次按类别和固定哈希切80%训练、20%当轮门控；同一ID不得同时进入候选训练和当轮门控。
- 只有更早已反馈批次可进入回放；当前门控样本在本轮训练中不可见。

## 门控与选择

- 候选相对父模型在当前20%门控集上Macro-F1不退化；
- 在Batch 1锚点上的Macro-F1下降不超过0.03；
- 只有通过门控的候选成为下一批父模型；拒绝候选不进入链；
- 开发选择先最大化Batch 2—5平均prequential Macro-F1，再最大化最差批次；复杂回放只有比`current_only`平均至少高0.005才可选，否则保持简单策略。

## 证据边界

Batch 6—7已在历史代理工作中暴露，不能称真正独立测试；本实验保证的是不参与本轮选型。所有派生JSONL和检查点写入独立运行根，原始Gas文件和官方训练包只读。官方试运行、PyTRiO和SwanLab均不使用。
