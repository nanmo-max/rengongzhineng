# 统一实验协议

本协议适用于代理数据、官方公开包、B包回放及全部消融。未满足本协议的运行只能标记为探索，不得用于正式结论。

## 1. 实验预注册

实验开始前登记：实验ID、研究问题、数据版本、可见性、切分、对照、指标、资源预算、随机种子、停止条件、成功标准和预期产物。默认随机种子为 `20261106`；正式策略另由队友完成一次干净环境独立复现 `[D-015]`。

PyTRiO实验还必须预登记模型配置名（不含密钥）、提示模板版本、提案schema版本、每轮最大调用数、Token/费用上限、超时和确定性降级策略。运行记录保存请求/响应哈希、解析状态、Token、延迟与失败类别；不得保存凭据或未经允许的逐样本数据。

## 2. 数据防泄漏

- 缓冲区用途必须显式登记：Anchor永不训练；Update是当前训练数据；Gate本轮只验证且不参与预处理/校准/阈值；Replay只来自完成一轮隔离的历史合法反馈。
- 预处理、填补、特征选择、权重和目标变换必须只拟合该候选实际训练集合，即Update或Update+eligible Replay。
- 执行层不得接收完整原始数据根；每轮只通过只读manifest和物化目录接收合法文件。未来批次诱饵测试是进入集成实验的硬门。

- 被评分样本必须先预测，再接收或使用其标签。
- `labeled_train_then_predict` 只允许训练集与被评分集是不同样本。
- 时间数据按时间、设备或轨迹切分，禁止随机打乱未来记录进入训练。
- 标准化、特征选择、阈值、校准和HPO只能拟合训练/开发数据。
- 密封测试段只运行一次；查看后不得继续选型。
- B包不得将未来批次、真实标签或私有特征写入公开记录。
- 每次实验保存样本ID/时间范围的不可逆摘要，用于审计重叠但不泄露原始内容。

## 3. 强基线

当前正式路线最低对照集：

1. 官方静态基线；
2. 简单固定低成本更新；
3. BRACE无大模型；
4. PyTRiO + BRACE；
5. 实验证明有效的论文方法及必要消融。

性能触发式单动作更新继续作为可选强基线。若PyTRiO+BRACE没有带来性能、资源、恢复或失败规避价值，必须保留负结果，不得用主观包装替代实证 `[D-016]` `[D-035]`。

## 4. 评测顺序与指标

统一采用prequential顺序：预测 -> 记录 -> 合法标签反馈 -> 更新。

记录：

- 官方主指标及方向；
- 累计prequential性能；
- 漂移流平均增益；
- 最差阶段与历史阶段退化；
- 恢复所需批次数；
- 迭代次数和单次周期；
- CPU时间、峰值内存、磁盘和镜像大小；
- 标签用量；
- 模型服务调用、Token、延迟和费用；
- 候选上线、拒绝和回滚次数。

不在官方公式公布前自创一个掩盖资源差异的总分 `[D-017]`。

## 5. 不确定性

- 分类任务按类别与阶段分层重采样。
- RUL按设备ID、退化轨迹或连续时间块重采样，禁止独立样本bootstrap。
- 样本数不足时不强行计算稳定区间，默认保留当前稳定模型。
- Bootstrap只说明样本/窗口不确定性，不宣称跨随机种子稳定。

## 6. 资源计量

每个候选独立记录墙钟时间、CPU时间、峰值RSS、输入样本数、标签数、候选数、模型服务Token和费用。正式评测资源口径发布后，以官方计量覆盖本地估算 `[H-003]`。

默认约束为每批最多2个候选、全程最多8个真实候选、单批最多消耗初始总CPU预算20%、最后3批至少保留25%预算；有界HPO最多3个内部试验。影子前任推理的CPU、RSS和延迟必须计入同一资源账本。评分公式未知时只维护性能—成本Pareto集合。

## 7. 消融

必需消融：

- 去预算约束；
- 去风险门控；
- 去历史收益反馈；
- 固定动作顺序替代自适应动作选择；
- PyTRiO关闭/开启；
- 若使用持久化Sampler，则基础Qwen3.5-4B与Sampler对照。

每次只改变一个因素，并保持数据可见性、预算和初始模型一致。

## 8. SwanLab与审计

开发阶段只保存本地私有审计，不要求生成或同步SwanLab记录。官方协议、最终工程模型和平台记录规范冻结后，通过正式重新训练生成最终实验记录；届时公开SwanLab只记录模型配置、训练曲线、合法聚合指标、资源、运行ID和哈希。私有审计日志保存事件顺序、批次状态和故障信息。平台未明确允许前，不公开B包逐样本预测、标签、特征、样本ID或密钥 `[B-SWANLAB-001]` `[H-004]` `[D-013]` `[D-023]`。

## 9. 失败分析

失败类型至少分为：数据/协议、训练数值、资源、统计证据不足、候选性能、回滚、日志、外部模型服务。失败实验必须记录根因、影响范围、是否可重现和下一步，禁止删除负结果。

## 10. 结果验收

正式结论必须同时具备：固定代码提交、数据指纹、配置、完整日志、基线对照、资源计量、失败说明和可复现命令。若缺少任一项，只能标记为“观察”，不得写入答辩核心结论。

任务性能优化还必须满足：训练/开发/独立确认身份已冻结；主指标改善不是只来自训练集；最差阶段和资源没有越过预注册安全界；所有公开验证读取均记账。开源方法必须附论文/代码版本、许可证和补丁记录。最终SwanLab只通过冻结完成品的正式重训产生，不回填早期探索。
