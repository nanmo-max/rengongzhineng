# P5-1B 决策记录

## 决策状态

`ANALYSIS_COMPLETE / IMPLEMENTATION_REQUIRES_APPROVAL`

P5-1A结论保持`FAIL_STATISTICAL_GATES_STOP`。本轮没有修改源码、冻结验证配置、Docker或正式RC，没有运行训练、远程模型或新统计实验。

## 结论

36项失败可归并为五个根因：

1. **需改代码：参考纳入语义错误。** “未检出漂移”被当作“可进入参考池”，直接造成异常值100%污染，并会放大漏检漂移的后续风险。
2. **需改代码并重新开发验证：中等尺度/噪声功效不足。** 大效应通过、成功确认后定位正确，说明不是整个检测器失效；需要先补统计贡献收据，再竞争尺度专用统计或合法序贯累积。
3. **需改接口：组组成能力缺失。** 当前没有组身份，只能间接检测边际混合分布，不能区分组比例与组内变化。
4. **需改校准设计/代码：BY不是实际fallback。** 当前BY依赖同一合法置换，非法交换性时不可达；2047次置换的p值分辨率也不可能通过24—128维BY第一顺位门。BY不能修复无效边际p。
5. **只需增加验证规模：相关结构置信区间不足。** 每格6条流即使0假警报，Wilson上界仍为0.390；至少35、建议40条独立流。三个1/24窗口FPR超门在该规模下不能证明系统性失控。

## 最小批准包建议

若进入P5-1C，批准范围应严格限制为：

1. 诊断收据增强；
2. 显式参考纳入资格；
3. 尺度/噪声候选统计的全新开发种子竞争；
4. 可选组合同与组感知证据；
5. maxT/BY校准来源重构；
6. 全新独立确认，相关结构每格至少35条流。

不得同时进入诊断归因、Qwen、训练器、Docker或正式RC集成。

## 哪些问题不是代码缺陷

- 相关结构运行级Wilson上界失败：独立流数量不足。
- 三个相关结构单窗FPR点失败：每格只有24窗，单个WARNING即为0.0417；需要扩大规模判断。
- 1秒目标未达到：它在P5-1A中是非门控目标，30秒工程门已通过。

## 哪些失败是派生结果

- 方差/噪声未确认时，延迟和Recall@k为空并分别触发失败；它们不是独立算法根因。
- BY非法交换性覆盖失败背后不是缺一条测试数据，而是现有代码路径和统计依据都不支持该声明。

## 风险判断

在修复并通过新独立确认前，漂移监测核心仍不得接入正式RC。最高优先级是参考污染修复，因为它是确定的状态语义错误；其次是BY语义修正。尺度/噪声方法需通过新开发竞争，不应在本轮提前锁定某个算法。
