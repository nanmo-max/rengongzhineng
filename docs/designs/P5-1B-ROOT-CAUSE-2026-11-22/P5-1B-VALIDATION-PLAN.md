# P5-1B 修复验证计划

## 1. 原则

P5-1A全部结果、配置和原始收据保持只读。修复验证使用新的实验ID、配置文件、输出根和三组互斥种子；所有种子在运行前提交冻结，并排除P5-1A的`510001..580001`范围。P5-1A最终种子不用于选择统计量、阈值、状态规则或验证规模。

本计划是待批准方案，本轮没有执行任何新验证。

## 2. 阶段与数据隔离

### 阶段0：证据封存

- 记录P5-1A配置、主JSON、原始manifest/records/summary的SHA-256。
- 建立只读输入清单；修复代码不得写入原输出目录。
- 红灯测试确认旧结果不会被新脚本覆盖。

### 阶段1：确定性单元与状态测试

不需要随机最终流：

1. `STABLE`但`reference_eligible=false`的异常窗永不进入活动参考。
2. 质量失败不确认统计漂移，但进入拒绝/隔离账本。
3. 恢复后只有满足资格的新窗可延迟纳入。
4. BY没有有效边际p来源时失败关闭。
5. maxT块跨边界、组数不足和时间交换性未知时失败关闭。
6. 组比例变化与组内变化输出不同事实类型。

### 阶段2：全新修复开发集

在运行前冻结`repair_calibration`和`repair_development`种子清单。开发比较：

- 原尺度统计基线；
- Brown–Forsythe型统计；
- log-MAD/log-IQR联合统计；
- 可选的非重叠窗口序贯累积。

场景至少包含：无漂移、厚尾无漂移、中等/大方差、噪声增加、少量异常值、均值漂移、多特征漂移、组比例变化、组内变化、恢复。维度仍为24/34/128，置换主臂仍为2047。

只用开发集选一个修复方案。选择准则按顺序：运行级误报与污染硬门、方差/噪声TPR、延迟、定位、CPU/RSS。若没有候选同时改善TPR且守住误报与异常值门，则停止，不进入确认。

### 阶段3：冻结修复候选

提交以下内容后才生成确认种子：

- 精确算法与状态规则；
- 统计量族和多重校正；
- 接受标准；
- 资源预算；
- 组合同和交换性条件；
- 修复候选Git提交。

### 阶段4：全新独立确认

使用从未参与阶段2的`repair_confirmation`种子，一次性运行。确认失败后只报告，不在同一确认种子上继续调参。

## 3. 独立重复规模

### 3.1 误报与相关结构

- 主无漂移：每维40条独立流。
- 每个维度×每种相关结构：至少35，建议40条独立流。零运行误报时，35条流的Wilson 95%上界约0.0989，才能检验≤0.10门。
- 每条流内窗口用于窗口FPR和连续性轨迹；运行级置信区间仍只以流为单位。

### 3.2 检出与恢复

- 中等/大方差、噪声、组成变化：每维至少40条独立流，以避免8条流造成的宽区间。
- 异常值、短暂漂移、反向恢复：每维至少40条独立流。
- 特征定位仅在确认事件上报告，同时报告“无确认导致不可评价”的比例，避免条件指标掩盖低检出率。

## 4. 验收标准

除下列语义修正外，保留P5-1A数值门：

- 运行级误报点估计≤0.05且Wilson上界≤0.10；
- 中/大效应事件检出率≥0.80；
- 中位延迟≤2窗；
- Recall@k≥0.80；
- 异常值不得直接确认，参考污染率必须0；
- alpha超支0；
- 4核/8核每窗CPU和墙钟≤30秒、RSS增量<1GiB；1秒仍为非门控优化目标。

BY验收需经人工批准后修订为：

1. 有有效边际p来源时验证BY的FDR与功效；
2. 没有有效边际p来源时必须失败关闭；
3. 不再要求BY把无效交换性本身“修复”为可检验。

这属于新实验的前瞻性语义修正，不回写P5-1A的`coverage.by_invalid_exchangeability`失败。

## 5. 统计输出

每个场景报告：

- 窗口FPR、确认FPR、运行级FPR；
- TPR、漏报率、延迟、Recall@k；
- 参考污染率与恢复时间；
- 95% Wilson或流级bootstrap区间；
- 每道门的拒绝数量；
- 统计量贡献和校准来源；
- CPU、墙钟、峰值RSS和实际置换数。

不允许把同一流多个窗口当独立统计重复，不允许只报告成功确认后的定位而省略未确认比例。

## 6. maxT交换性检查

在每个作业中记录：

- 置换单位是完整设备组、合法时间块还是独立批次；
- 块是否跨参考/当前边界；
- 组数量与大小；
- 是否存在需要分层的工况；
- 为什么认为单位可交换；
- 不满足时选择何种有效边际校准，或为何失败关闭。

仅传入一列`block_ids`不等于自动证明交换性。

## 7. 预计资源

按P5-1A 128维2047次置换约5.3秒/窗估算，相关结构确认臂约`3×4×40×4=1,920`窗，约10,200 CPU秒；方差/噪声/组成和恢复目标臂还需约10,000—12,000 CPU秒。4并发理想墙钟约1.5—2小时，另加候选开发与I/O。该数值只是规划估计，不能写成实测。

不得通过减少置换次数换取速度；若候选统计量使30秒硬门失败，则该候选不晋级。

## 8. 停止条件

- 参考污染不为0；
- 运行级误报门失败；
- 新尺度统计只提高TPR但破坏厚尾/异常值负对照；
- 组检验使用了行级伪独立；
- BY使用无效边际p；
- 资源硬门失败；
- 确认集任一硬门失败。

触发停止后保留全部负结果，禁止在同一确认种子上继续修补。
