# P5-1B 统计验收失败根因分析

## 1. 范围与证据边界

本报告只分析`P5-DRIFT-STATISTICAL-VALIDATION-001`已经冻结的结果、原始收据和当前源码，不修改检测器、最终验证配置或种子。P5-1A的结果仍为`FAIL_STATISTICAL_GATES_STOP`，不得被本报告重解释为通过。

证据等级：

- **直接证据**：冻结结果JSON、666条最终作业收据、36条失败检查、源码控制流。
- **数学推导**：Wilson区间所需样本量、BY最小可拒绝p值与置换分辨率的关系。
- **待开发验证的机制假设**：某个新增尺度统计量或序贯累积方法能否提高检出率。本报告不把这些假设写成已经有效。

P5-1A未保存每轮每特征的五个原始统计量、标准化值、经验p值和调整p值，只保存状态与选中特征。因此可以证明“在哪个门之后失败”，但不能仅凭现有收据断言位置、尺度、Wasserstein或KS中的哪一个对每条流贡献最大。该信息缺口必须先通过新的开发期诊断收据补齐，不能用P5-1A最终种子重跑来补。

| --- | ---: | ---: | --- |
| A. 中等方差漂移 | 8 | 1—2 | 3个检出率、3个延迟/定位派生失败及2个额外延迟失败；大型方差漂移已能检出 |

## 3. A类：中等方差漂移检出不足

### 3.1 预注册目标与结果

目标为中/大效应事件检出率至少0.80、检测延迟中位数不超过2个窗口、确认时Recall@k至少0.80。

| 维度 | 中等方差事件检出率 | 95% Wilson区间 | 延迟 | 定位 |
| ---: | ---: | --- | --- | --- |
| 24 | 0/8 = 0.000 | [0.000, 0.324] | 无 | 无 |
| 34 | 1/8 = 0.125 | [0.022, 0.471] | 3 | 1.000 |
| 128 | 0/8 = 0.000 | [0.000, 0.324] | 无 | 无 |

对照：大方差漂移在24/34/128维均为7/8 = 0.875、延迟1、定位1.0。这证明尺度路径并非完全失效，而是中等效应在当前样本量、窗口alpha和高维maxT门下功效不足。

### 3.2 代码路径

- 尺度效应只由`abs(log(IQR_current / IQR_reference))`表达：`src/brace_formal/drift.py:179-250`。
- 五个统计量先按置换零分布稳健标准化，再以最大值形成特征内omnibus：`src/brace_formal/drift.py:401-425`。
- `maxT`再取所有特征的最大omnibus校正窗口内FWER：`src/brace_formal/drift.py:429-433`。
- 最终同时要求`adjusted_p <= 0.005`和`omnibus >= 2.0`：`src/brace_formal/drift.py:436-441`。
- 状态机要求连续两个WARNING才确认：`src/brace_formal/drift_state.py:258-273`。

### 3.3 根因判断

**高可信根因：统计功效不足而非定位失效。** 中等尺度变化只作用于一个特征、每窗80行，却同时承担特征内五统计联合、24—128维窗口级FWER、每轮0.005 alpha和两连确认。已检出的唯一中等方差流定位正确；大效应稳定通过，符合“门过严/统计量效率不足”的功效模式。

**尚未证实的子根因：现有IQR尺度统计效率不足。** 对近似连续分布，IQR稳健但相对方差类统计效率较低；Wasserstein和KS也会响应尺度变化，但现有最终收据没有保留各统计量的标准化贡献，不能断言是IQR、联合标准化还是全局maxT中的某一项单独造成失败。

**共同放大因素：未检出即参考可纳入。** 中等方差流大量被标为STABLE，并在一轮延迟后进入活动参考账本。该问题与D类污染同根，会在真实更新参考数组的系统中进一步削弱后续检出；P5-1A检测器仍固定使用最初`reference`数组，所以本次检出率尚未被该账本污染反向影响。

### 3.4 最小修复方向与副作用

1. 先增加开发期诊断收据，保存五统计量、标准化值、经验p、调整p和被哪一道门拒绝；不改变决策。
2. 仅在新的修复开发种子上比较尺度专用候选统计量：稳健Brown–Forsythe型绝对偏差、log-MAD/log-IQR联合尺度分数，以及不复用样本的持续尺度证据累积。
3. 保留同步maxT与alpha账本，不直接降低alpha或取消多重控制。
4. 将“未检出”与“有资格进入参考池”分离，避免漏检窗口污染基准。

副作用包括统计量族增加后的多重控制成本、序贯累积带来的恢复延迟，以及额外CPU开销。任何候选必须在新开发流上同时检查FPR，不能只追求TPR。

## 4. B类：噪声增加检出不足

### 4.1 预注册目标与结果

| 维度 | 事件检出率 | 95% Wilson区间 | 延迟 | 条件定位 |
| ---: | ---: | --- | --- | --- |
| 24 | 1/8 = 0.125 | [0.022, 0.471] | 2 | 1.000 |
| 34 | 2/8 = 0.250 | [0.071, 0.591] | 2.5 | 1.000 |
| 128 | 0/8 = 0.000 | [0.000, 0.324] | 无 | 无 |

定位在成功确认时为1.0，主问题仍是检出功效而非特征排序。

### 4.2 数学与工程原因

合成噪声是向单一特征加入均值为0的独立噪声：`scripts/run_p5_drift_statistical_validation.py:209-212`。它主要表现为尺度、尾部和形状变化，而位置中位数理论上近似不变。当前检测器没有噪声专用的稳健尾部/绝对偏差统计，只能依赖IQR、Wasserstein和KS间接响应；之后仍经过与A类相同的FWER、0.005 alpha和两连确认。

A与B大体共享“尺度/形状中等效应功效不足”根因，但不能完全合并：方差乘法保持原分布形状，附加噪声会改变尾部和信噪结构，需要分别验证统计量。

### 4.3 最小修复方向与副作用

- 复用A类的尺度专用诊断与候选统计，不另造任务专属规则。
- 增加稳健尾部跨度或绝对偏差统计只能作为预注册候选，并纳入同一置换校准；不得用固定阈值绕过maxT。
- 若采用跨窗累积，只能累计互不重叠的新窗口，恢复时必须重置，避免把短暂噪声永久积累为漂移。

副作用是对厚尾正常数据可能更敏感，必须新增厚尾无漂移负对照和异常值场景，防止修复B类却破坏D类。

## 5. C类：组组成变化检测不稳定

### 5.1 实际结果

24/34/128维事件检出率分别为0.625、0.750和0.250；确认后的Recall@k分别为0.933、0.944和1.000。失败集中在“是否确认”，不是确认后的定位。

### 5.2 根因

验证生成器先按参考组概率0.5和当前组概率0.8生成隐式二元组，再对三个真值特征施加组偏移：`scripts/run_p5_drift_statistical_validation.py:170-184, 511-520`。但是组标签在生成后被丢弃，`DriftMonitor.compare`只接收特征矩阵和置换块ID：`src/brace_formal/drift.py:343-354`。系统因此无法直接检验“组比例变化”，只能期待混合分布的边际中位数、IQR、Wasserstein或KS足够大。

该场景名义上是“中等组组成变化”，但边际均值变化约为`(0.8-0.5)×1.5=0.45`个参考尺度，明显弱于预注册的单特征中等均值漂移1.5。因此它不是与均值中等效应同难度的场景。这里同时存在能力缺口和场景标度不一致，不能只靠调阈值解决。

### 5.3 最小修复方向与副作用

- 为监测接口增加可选且不可逆的组摘要/组ID合同，明确区分：组比例改变、组内分布改变、二者同时改变。
- 有合法组信息时使用组级比例检验或完整组置换；没有组信息时只报告“边际混合分布变化”，不能声称完成组组成归因。
- 组身份不能按数据集名称推断，也不能把同一设备内行当作独立组。

副作用是接口扩展和隐私/基数约束；组数不足时必须返回`insufficient_group_support`，不能为了检出率把行级样本伪装为独立设备。

## 6. D类：少量异常值造成参考基准污染

### 6.1 直接路径证据

三个维度的8/8流均出现：监测状态序列全部为`stable`、直接确认率0、最终参考污染率1.0。一个典型轨迹为：

```text
stable → stable(outlier window) → stable → stable → stable
```

状态机在STABLE状态下把每个`Observation.STABLE`先放入`quarantine_ids`；当隔离队列长度超过默认1窗时，把最早窗口移入`active_reference_ids`：`src/brace_formal/drift_state.py:236-243`。验证器又把“报告不是WARNING”一律转换为`Observation.STABLE`：`scripts/run_p5_drift_statistical_validation.py:619-631`。因此异常窗未触发稳健漂移门后，下一窗到来即合法进入参考池。

### 6.2 根本原因

**系统把“没有足够证据拒绝稳定”错误等同于“已经获得可纳入参考池的稳定证据”。** 这是状态语义缺陷，不是alpha、maxT或异常值检出阈值问题。稳健检测器不把1/80极端值升级为持续漂移本来是正确行为，但参考池还需要独立的数据质量与纳入资格门。

同一缺陷也解释了中等方差、噪声和组组成漏检流中的高参考污染率，只是P5-1A的硬门仅对恢复场景检查污染。

### 6.3 最小修复方向与副作用

- 引入独立的`reference_eligible`/`data_quality_ok`证据，不再由`DriftStatus.STABLE`自动推导。
- 少量极端值、缺失突增、契约异常窗口可保持“不确认漂移”，同时标记为“不允许进入参考池”。
- 只有通过质量门、无漂移证据、延迟复核和必要的等价/稳定性条件后才能入池。
- 保持当前活动参考不变；不需要提高异常值漂移灵敏度来修污染。

副作用是参考池增长变慢，早期历史可能不足；系统应显式返回参考不足，而不是降低纳入门槛。

## 7. E类：相关结构置信区间与BY降级

### 7.1 相关结构附加臂的15项失败

每个维度×相关结构只有6条独立流、每条4窗。所有12个单元的运行级假警报点估计均为0，但0/6的Wilson 95%上界为0.3903，无法满足上界≤0.10。要让零失败时Wilson上界≤0.10，至少需要35条独立流；主无漂移臂使用40条流并通过，上界为0.0876。

三个窗口FPR失败单元均为24个窗口中1次WARNING，即1/24=0.0417。样本量如此小时，任何一次WARNING都会超过0.01点门；这与运行级确认仍为0并不矛盾。

因此这15项首先是**验证精度不足**，不是已证明的相关结构误报失控。扩大到每格至少35、建议40条独立流即可检验；不得把同一流的多个窗口当独立流来收窄运行级区间。

### 7.2 BY不是可用的无交换性fallback

当前实现先无条件调用`_permutation_masks`；块非法时在进入BY分支前直接返回`INSUFFICIENT_CALIBRATION`：`src/brace_formal/drift.py:379-399`。只有置换已合法完成后，才在`src/brace_formal/drift.py:429-435`选择maxT或BY。因此`by_fallback`只是“对合法置换产生的特征p值做BY”，不是无交换性时的fallback。

此外，在`alpha_window=0.005`、2047次置换下，最小经验p为0.000488。BY第一顺位可拒绝阈值为`alpha/(d×H_d)`：

| 维度 | BY第一顺位阈值 | 达到该分辨率至少需要的置换数 |
| ---: | ---: | ---: |
| 24 | 5.52e-5 | 18,124 |
| 34 | 3.57e-5 | 28,003 |
| 128 | 7.19e-6 | 139,088 |

所以当前BY在三种维度都不可能拒绝任何假设，实测中等均值漂移检出率均为0。这不是简单“保守”，而是预注册p值分辨率规则没有把BY的维度与调和因子纳入预算。

更重要的是：BY只控制一组**有效边际p值**的FDR，不能修复非法交换性产生的无效p值。若组/时间结构不支持置换，必须先找到对该结构有效的边际校准方法；否则正确行为仍是失败关闭。

### 7.3 maxT交换性边界

当前代码能发现块跨越参考/当前边界并失败关闭：`src/brace_formal/drift.py:268-280`。但它无法仅凭块ID证明设备组在窗口间可交换，也没有时间序列平稳性/分层条件。P5-1A的非法交换性测试只覆盖“块跨边界”这一结构错误，不能证明maxT适用于所有工业时间流。

## 8. 根因归并结论

| 根因 | 影响类别 | 类型 | 需改代码？ |
| --- | --- | --- | --- |
| R1：中等尺度/噪声功效不足，且缺少统计贡献收据 | A、B | 算法功效与可观测性 | 是 |
| R2：未检出被错误当作参考纳入资格 | D，并放大A/B/C | 状态语义错误 | 是，最高优先级 |
| R3：监测接口没有组组成信息 | C | 能力/接口缺口 | 是 |
| R4：BY依赖合法置换且分辨率不可能过门 | E | 校准设计与代码路径错误 | 是，或明确取消伪fallback并失败关闭 |
| R5：相关结构每格n=6不足以验证运行误报 | E | 验证规模不足 | 否，只需新验证规模 |

P5-1A证据应继续保留为失败基线。任何修复都必须在全新的修复开发种子上选择，再使用全新的独立确认种子一次性验收；不得重跑或优化到P5-1A最终种子。
