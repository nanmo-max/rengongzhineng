## Current understanding

- 项目目标不是单篇论文复现，而是在赛题约束下构建可离线、无人干预运行的工业模型自进化闭环。
- 用户计划本人承担核心技术，主要用 Codex 完成；队友承担低风险、可学习且不影响关键路径的技术任务，以及 PPT、计划书等展示工作。
- 论文策略是先从评分要求反推模块，再筛选有开源代码的一区 SCI 工作进行复刻与组合。
- 已核对的硬约束包括：3–5 名本科生、1–2 名指导教师；隐藏漂移测试流；统一离线环境；全实验留痕；性能不得低于静态基线；需要安全受控、可回滚；提交系统镜像、实验记录依据和运行说明。

## Design tree

1. **参赛准备与硬约束** — 资格、报名/校内推荐、团队、导师、官方群/平台/数据、时间与算力是否锁定。
2. **竞争目标与评分策略** — 目标是完成、企业赛前 20、北京市决赛还是冲奖；据此确定风险预算和主观/客观分配。
3. **核心技术路线** — Harness、持续微调或混合路线；定义受控 RSI 的边界与最小可行闭环。
4. **论文复现与证据路线** — 按模块筛选一区 SCI/顶会开源工作、基线、复现实验、组合创新及许可证合规。
5. **系统工程与评测** — 漂移监测、诊断归因、实验优化、评估上线、回滚、资源治理、SwanLab 留痕和离线镜像。
6. **执行节奏与人员分工** — Codex 工作流、个人关键路径、队友低风险任务、导师评审点和每日/每周里程碑。
7. **材料与答辩** — 运行说明、计划书、PPT、演示、证据链、答辩问题库与北京市决赛拔高项。

Dependencies: Branch 1 constrains all later branches. Branch 2 determines how aggressive Branches 3–7 may be. Branches 3 and 4 jointly determine Branch 5. Branch 5 must stabilize before Branch 7 can be finalized.

## Resolved decisions

- **Decision: 参赛资格与组织条件** — 已全部锁定：校内报名/推荐路径明确，团队满足 3–5 名本科生要求，指导教师满足 1–2 名要求，且已加入赛题群。
- **Decision: 公开数据过渡方案** — 官方数据尚未取得；先用机制相近的公开数据集开发，后续通过数据适配层替换为官方数据。
- **Decision: 实验记录迁移** — SwanLab/专属平台暂不可用；先在本机运行和验证，平台开放后重新运行正式实验并提交记录。
- **Decision: 竞赛目标** — 目标为北京市奖项（B4）。
- **Decision: 风险姿态** — 采用稳健底座加 1–2 个高价值创新（B9b）。
- **Decision: 优先级** — 稳定跑完 > 演示效果 > 客观性能 > 创新性 > 资源成本。
- **Decision: 推荐技术默认项** — Q13–Q20 暂均接受推荐项，但“微调为主、大模型为辅”的补充表述与 Q13 推荐架构存在待解决冲突。
- **Decision: 文献初选范围** — 当前选择 D3：不限分区，但要求高质量且有开源代码；与最初“一区 SCI”为主的表述待二次确认。
- **Decision: 核心技术主从关系** — 微调是技术骨架；大模型因资源与复杂度约束仅作为辅助，并且必须可关闭、可替换，不成为系统跑通的单点依赖。
- **Decision: 技术选择授权** — 用户不要求自己先掌握 A5/A6 涉及的技术术语；由 Codex 基于稳定获高奖目标提出并验证技术方案。
- **Decision: 开发预算** — 额外付费预算约 100 元，优先本地计算和开源方案。
- **Decision: 文献策略** — 主线优先一区 SCI 开源论文，CCF-A/顶会和其他高质量开源研究作为补充；主干论文数量由实际检索与复现价值决定。
- **Decision: 指导教师参与度** — 原则上不打扰指导教师，项目不得依赖教师的持续技术或材料支持。
- **Decision: 赛题优先而非能力优先** — 用户既有的 MCU、边缘部署、图像分类等能力只用于任务分配、学习成本与风险评估；不得据此改变公开数据集、论文、模型类型或技术路线。所有技术选择必须从官方数据、评分规则、评测约束与稳定获高奖概率反推。

## Provisional constraints to resolve in later branches

- **Constraint: 技术叙事与来源披露** — 对外叙事以独立问题定义、系统设计、实验发现和工业约束下的组合创新为主，不必把项目标签化为“论文复刻”；实际使用的开源代码、预训练模型和直接借鉴的方法仍必须遵守许可证并准确标注，不虚构原创算法归属。

## Confirmed assumptions

- 参赛学生均为北京地区普通高校在校本科生，且每人只参加这一支队伍。
- 团队已有 3–5 名学生和 1–2 名指导教师。
- 校内报名与推荐名额已经确定，不存在资格淘汰风险。
- 团队已加入赛题群，并有人负责跟进官方通知和截止日期。
- 当前开发机至少有 NVIDIA RTX 4060 Ti 和 AMD Ryzen 7 7800X3D；显存、内存、磁盘和操作系统仍待补充。
- 当前开发机为 RTX 4060 Ti 8GB、Ryzen 7 7800X3D、Windows 10；D 盘约 307GB 可用。已安装 Git、Python 与 Conda，当前未检测到 Docker。
- 用户预计每天投入约 3 小时；队员“3 小时，可增加”暂按每人每天约 3 小时理解，待共享理解确认时纠正。
- 团队除技术负责人外暂按三名队员理解：两名物联网专业大二学生、一名大数据专业大二学生，均只掌握基础知识；其中一人粗略了解 STM32 和人工智能。
- 技术负责人已有边缘部署、MCU、AI 图像分类/识别经验；从其他已授权读取的聊天可确认其接触过轻量视觉模型、知识蒸馏、开放集/持续学习、YOLO 与 MCU 部署方向。这是执行能力画像，不是本赛题的方向约束。
